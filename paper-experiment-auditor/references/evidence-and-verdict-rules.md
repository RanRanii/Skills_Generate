# 证据与判定规则

## 证据类型

每项证据分配唯一 `EVD-###`。Claim 与 finding 通过 ID 引用证据，避免在不同交付物中用无法对齐的自然语言重复描述。

- `PAPER`：稿件原文、公式、表格、图注或补充材料。
- `CODE`：实际被运行入口调用的源码。
- `CONFIG`：配置文件、CLI 参数、环境变量及其生效优先级。
- `ARTIFACT`：日志、checkpoint、预测、指标、表格数据或图片输入。
- `RUNTIME`：可复查的命令、环境、退出状态和输出。
- `DOC`：README、安装说明、数据或模型获取说明。

## 证据强度

从强到弱通常为：实际生效的运行记录、入口可达的源码和配置、生成产物、发布文档、注释或未被调用的示例。实际冲突时不得通过弱证据覆盖强证据。

## 状态判定

### VERIFIED

必须同时满足：

- 动态验证直接覆盖该声明；
- 运行命令、代码版本、配置和输入可识别；
- 产物可追溯；
- 结果满足预先声明的等价规则或容差。

### CONSISTENT

静态证据未发现冲突，且实现路径和生效配置可定位，但没有足够的动态复现证据。

### MISMATCH

论文期望与实际实现或结果存在可定位冲突。必须写出“期望值”和“实际值”，不能只写结论。

### UNVERIFIABLE

论文声明含义清楚，但缺少支持判定所必需的材料。列明缺少的具体证据，以及补充什么可以继续核验。

### AMBIGUOUS

论文或实现本身允许多个合理解释，因此无法唯一确定应核验的目标。列出竞争解释和需要作者回答的问题。不要仅因缺少文件就使用本状态；材料缺失通常属于 `UNVERIFIABLE`。

### NOT_APPLICABLE

该检查项与当前声明无关，并简述原因。

## 等价与容差

语法不同不一定构成冲突。先判断功能等价性，例如别名、封装、数学等价实现和由总 batch size 推导的梯度累积。数值结果比较必须事先说明绝对误差、相对误差、统计区间或随机重复标准，禁止见到结果后调整容差。

## 负面结论

“未找到实现”必须同时说明搜索范围和使用的定位方式。无法证明不存在时，应写成“在已检查范围内未找到”，并根据覆盖度选择 `UNVERIFIABLE` 或 `MISMATCH`。

## 静态与动态证据边界

源码、配置和已有产物属于静态证据，只能支持 `CONSISTENT`、`MISMATCH`、`UNVERIFIABLE` 或 `AMBIGUOUS`。`VERIFIED` 必须链接 `RUNTIME` 证据，且运行记录应包含命令、提交、环境、输入、退出状态和产物定位。仅成功导入模块或通过 smoke test，不足以验证论文数值声明。
