# 工作流 01：输入盘点与审计范围

## 目标

确认此次核验覆盖哪些论文声明、代码、配置、结果和发布内容，并把缺失材料转化为明确限制，不因非关键材料缺失而停止全部工作。

## 输入盘点

记录以下内容的实际路径、版本或缺失状态：

- 论文：源文件、PDF、补充材料、图表和版本日期。
- 代码：仓库根目录、当前分支、提交哈希、子模块和未提交改动。
- 配置：默认配置、实验配置、命令行参数、环境变量和调度脚本。
- 数据：来源、版本、划分文件、预处理缓存及公开限制。
- 结果：日志、checkpoint、指标文件、表格、绘图输入和生成脚本。
- 环境：依赖锁文件、Python/R/CUDA 等版本、硬件假设。
- 发布范围：计划提交到 GitHub 的文件和明确排除的私有或受限内容。

## 操作步骤

1. 识别仓库根目录和论文主文件，不根据目录名猜测最终用途。
2. 记录 Git 状态。未提交改动可能使本地结果与将发布版本不同，必须在报告中注明。
3. 将材料分为“存在”“缺失”“存在但不在发布范围”“需要用户确认”。
4. 选择核验模式：声明提取、静态审计、结果溯源、动态复现或修复复核。
5. 使用 `templates/audit-intake.md` 创建范围卡。

## 停止条件

仅当无法定位任何论文实验描述或任何待审计实现时停止，并向用户索要最小必要输入。其余缺失项不应阻断可执行的核验，应在后续标记为 `UNVERIFIABLE`。

## 输出

- 审计范围卡
- 输入缺口清单
- 计划执行的工作流
- 动态运行前是否仍需授权
