# 工作流 07：行为评测与版本发布门禁

## 触发条件

更新 Skill 的判定规则、工作流、结构化输出或确定性脚本，并准备发布 Skill 新版本时使用。普通论文审计不加载本工作流；论文代码仓库的发布审查使用 Workflow 08。

## 开始前读取

- `references/behavioral-evaluation.md`
- `references/audit-output-schema.md`

## 原则

- 评测案例与 oracle 分离；被评测实例不能看到预期答案。
- 评测输出写入 Skill 目录之外的隔离临时目录，评分完成后清理，不进入版本提交。
- 优先检查行为不变量，不比较固定措辞。
- 保留 clean control，避免通过增加激进规则提高检出率却扩大误报。
- 只根据可复现的失败修改 Skill，不为单个样例积累通用硬规则。

## 执行步骤

1. 运行全部单元测试。
2. 校验 `evals/cases` 的结构、路径和 oracle。
3. 对每个案例启动独立核验，将 `<case-id>.json` 输出到隔离临时目录。
4. 校验结构化输出。
5. 使用 grader 与 oracle 比较。
6. 汇总遗漏、误报、证据幻觉、状态错误和严重性错误。
7. 必要修改后重新运行完整套件。
8. 运行 Skill 快速校验、Markdown 链接检查和 Git diff 检查。
9. 仅在全部门禁满足后提交并创建版本标签；已存在的版本标签不得重写。

## 失败处理

- 遗漏 blocking finding：阻止发布。
- Clean control 出现 `BLOCKER`/`MAJOR`：阻止发布。
- Evidence 指向不存在文件：阻止发布。
- 无 `RUNTIME` 证据却标记 `VERIFIED`：阻止发布。
- 分数低于 85：记录失败维度并修正后全量回归。

## 输出

- 单元测试结果
- fixture 校验报告
- 每个案例的结构化输出和评分结果
- 门禁汇总
- 版本提交与标签（仅门禁通过后）
