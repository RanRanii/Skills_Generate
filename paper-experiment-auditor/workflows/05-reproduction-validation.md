# 工作流 05：复现与动态验证

## 目标

在静态审计完成后，用最小充分的执行验证论文声明、公开入口和结果生成链路。

## 开始前读取

- `references/reproducibility-rules.md`
- `references/evidence-and-verdict-rules.md`
- `references/result-traceability.md`

## 运行前门槛

先完成并报告：

- 要验证的 `CLM-###`
- 拟执行命令及预计时间、硬件、存储和网络需求
- 是否需要下载数据、模型或调用外部服务
- 是否会覆盖现有结果、checkpoint 或缓存
- 成功标准与允许误差

低成本、无副作用的已有测试或 dry run 可直接执行；长时训练、大型下载、GPU 任务或外部付费调用必须取得用户明确授权。不得为通过复现而修改实现。

## 分层验证

按成本递增执行：

1. 环境和依赖可解析性检查。
2. 命令帮助、配置解析和入口 smoke test。
3. 小样本或单 batch 前向、训练和评估路径。
4. 指标或结果聚合的确定性样例验证。
5. 用户授权后的完整或缩减复现。

每次运行记录命令、工作目录、提交哈希、环境、输入、随机种子、退出码、关键输出和产物路径。使用 `templates/reproduction-log.md`。

若复现输出与论文结果均可整理为结构化表格，可按 `references/script-usage.md` 使用 `scripts/compare_result_tables.py` 保存可复查的差异记录。容差必须在执行比较前写入复现记录。

## 判定升级

只有当运行证据直接覆盖声明、产物可追溯且偏差在预先定义的容差内时，才可从 `CONSISTENT` 升级为 `VERIFIED`。smoke test 只能验证流程可启动，不能验证论文结果已复现。

## 失败处理

区分：

- 环境或依赖失败
- 数据或模型不可得
- 命令或文档错误
- 代码运行错误
- 结果数值不一致
- 资源不足或运行被中断

保留原始失败证据。未经用户明确要求，不进入修复工作流。
