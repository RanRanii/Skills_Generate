# 工作流 03：代码与配置映射

## 目标

定位每条论文声明在准备发布仓库中的实现、配置入口和运行路径，识别真正生效的值。

## 开始前读取

- `references/experiment-checklist.md`
- `references/evidence-and-verdict-rules.md`

## 映射顺序

1. 识别公开入口：README 命令、主脚本、CLI、notebook、workflow 或 shell 脚本。
2. 跟踪入口加载的配置、默认值、参数覆盖、环境变量和自动推导逻辑。
3. 跟踪数据从原始输入到模型输入的完整变换链。
4. 跟踪模型构建、损失计算、反向传播、验证、checkpoint 和测试流程。
5. 跟踪指标从预测值到最终表格或图片的计算与聚合路径。
6. 为每个 `CLM-###` 填写实现与证据位置。

当配置文件数量较多时，读取 `references/script-usage.md`，使用 `scripts/collect_config_values.py` 生成扁平配置清单。脚本结果只表示文件中声明的值；仍需沿入口和覆盖关系确认实际生效值。

## 证据定位要求

优先记录稳定定位信息：

- 仓库相对路径
- 函数、类、命令或配置键名称
- 可用时记录行号，但不得只依赖容易漂移的行号
- 配置来源及其优先级
- 生成结果文件的实际命令或调用链

同一参数存在多处定义时，必须说明覆盖顺序。不要把示例配置、废弃脚本或未被入口引用的代码误认为实际实现。

## 发布完整性检查

同时检查新用户克隆仓库后能否获得：

- 可发现的运行入口与参数说明
- 依赖或环境定义
- 配置文件和必要的小型元数据
- 数据获取或准备说明
- checkpoint 或下载说明（若论文复现需要）
- 结果生成与评估命令
- 不依赖作者本机绝对路径、未提交模块或私有文件的流程

## 输出

- 初步 Claim–Code Matrix
- 未映射声明列表
- 配置覆盖关系
- GitHub 发布缺口列表
